# OpenMVIS — project site and benchmark

Source of [openmvis.com](https://openmvis.com): the documentation of
[MVIS](https://github.com/openmvis/openmvis), the multi-visual-inertial sensor
calibration toolbox, the OpenMVIS datasets, the device wiki and the public
calibration results.

The site is built with [Astro](https://astro.build) and the
[Starlight](https://starlight.astro.build) docs theme. GitHub Pages serves the
committed build in `docs/`.

> **Vision.** OpenMVIS aims to become the public benchmark for camera and
> visual-inertial sensor calibration, the role KITTI plays for driving. See
> [`doc/PLAN.md`](doc/PLAN.md) for the roadmap and [`doc/DESIGN.md`](doc/DESIGN.md)
> for the architecture.

## Quick start (developing the site)

Prerequisites: Node 22 (via [nvm](https://github.com/nvm-sh/nvm) recommended).

```bash
nvm use 22                  # or `nvm install 22` first
cd site/
npm ci
npm run dev                 # http://localhost:4321
```

Build the static site:

```bash
npm test                    # the post-build rename and redirect steps (node --test)
npm run build               # astro build into ../docs, then post-build.mjs renames _astro/ and writes moved-page redirects
PYTHONNOUSERSITE=1 python3 scripts/check_moves.py   # after every build: old addresses redirect, no broken internal links
npm run preview             # serve the built site locally
```

## Deploying

There is no separate deploy step. `npm run build` writes `docs/`, GitHub Pages
serves `main:/docs`, so a pushed build on `main` is live within minutes. Commit
the source and the build together.

Astro empties `docs/` on every build; anything that must survive a build lives
in `site/public/` (the `CNAME`, `.nojekyll`, the media and download folders,
and the redirect stubs that keep the old page addresses working).

CI (`.github/workflows/ci.yml`) runs `npm test`, `npm run build` and the
Python tests on every push to `main` and every pull request; it does not
commit a build.

## Generated data and the Python lib

Sensor pages, the results tables and the UZH-FPV table are generated by the
Python lib in `python/mvis_site` (see [`python/README.md`](python/README.md)).
The scripts in `site/scripts/` only call it. The run folders, the private
sensor config and the results snapshots stay outside this repository and are
passed by path:

```bash
PYTHONNOUSERSITE=1 python3 site/scripts/export_sensors.py --private-config <sensors.yaml> --media <clips dir>
PYTHONNOUSERSITE=1 python3 site/scripts/export_examples.py --private-config <sensors.yaml>
PYTHONNOUSERSITE=1 python3 site/scripts/export_uzh.py --leaderboard <leaderboard dir> --uzh-root <uzh study dir>
PYTHONNOUSERSITE=1 python3 site/scripts/export_board.py --leaderboard <leaderboard dir> --records <snapshot> --results-commit <its full sha>
PYTHONNOUSERSITE=1 python3 site/scripts/export_repeatability.py --records <snapshot> --stats <three_way_compare_stats.json of that batch> --batch <batch> --results-commit <its full sha> [--leaderboard <leaderboard dir>]
PYTHONNOUSERSITE=1 python3 site/scripts/export_results.py --leaderboard <leaderboard dir> --records <snapshot> --stats <its stats file> --batch <batch> --results-commit <its full sha> --uzh-root <uzh study dir>   # after the three above
cd python && PYTHONNOUSERSITE=1 python3 -m pytest -q     # unit tests; python/cov.sh for coverage
```

Use Python 3.12 with numpy < 2; the export scripts refuse numpy 2.

What each writes:

| Script | Writes |
|---|---|
| `export_sensors.py` | `site/src/data/sensors/*.json`, `sensor.css`, `site/src/scripts/sensor-page.js`, `site/src/data/sensor-nav.json`, `site/src/content/docs/devices/*.mdx`, `site/public/media/sensors/<slug>/` |
| `export_examples.py` | `site/src/data/examples/*.json`, `site/src/data/examples-nav.json`, `site/src/content/docs/benchmark/examples/*.mdx`, `site/public/media/examples/<slug>/` (reads the `examples:` run map of the private sensors.yaml; an example whose run has no views yet is written without player, map and result) |
| `export_board.py` | `site/src/data/leaderboard/board.json`, `board.css` |
| `export_uzh.py` | `site/src/data/leaderboard/uzh_fpv.json` |
| `export_repeatability.py` | `site/src/data/leaderboard/repeatability.json` (matched-recording repeatability per family and group; reads the private per-recording stats file, writes derived spreads only) |
| `export_results.py` | the Results pages: `site/src/data/eval/index.json` (Leaderboard rows), `eval/<slug>.json` + `site/src/content/docs/benchmark/results/<slug>.mdx` (one Dataset eval page per dataset), `site/src/data/results-nav.json` (sidebar, old-hash jumps); text from `python/data/public_results.yaml`, ◆ counted by the Space's code and checked against `board.json`, only min/max per row and tool from the private stats file |

The page text is public (`python/data/public_sensors.yaml`,
`public_examples.yaml`, `public_results.yaml`); run paths never enter this
repository. Every sensor text drawn from the data (page JSON, MDX, process
figures, sidebar) goes through a public lint first; see `python/README.md` for
the exact list. Edit the data or the lib, never the generated files.

After a build, `check_moves.py` checks that every address in
`site/src/data/moved.json` redirects straight to its new page and that no
internal link is broken.

Browser and media checks: `nav_check.py`, `responsive_check.py` (homepage
matrix; `--pages /a/,/b/` for content pages at 390 and 1360 px in light and
dark), `hero_sync_check.py`, `hero_labels_check.py` (Playwright with the system
Chrome) and `check_hero_media.py` (ffprobe). Their rules are in
`mvis_site/checks.py`.

## Adding content

### A new doc page

Create an MDX file under `site/src/content/docs/` matching the URL you want.
Example — `site/src/content/docs/calibration/my-page.mdx`:

```mdx
---
title: My Page
description: Short description used by search and social cards.
---

## Heading

Body content. Inline math: $f_x = 287.84$. Display math:

$$
\arg\min_{\boldsymbol{x}} \sum_i \rho(\|\mathbf{r}_i\|^2)
$$
```

Then add the page to the sidebar in `site/astro.config.mjs`. If a page moves,
add its old address to `site/src/data/moved.json` so the build writes a
redirect.

### Results and devices

The results tables and the device pages are generated (see above). To change
their words, edit `python/data/public_*.yaml`; to change their numbers, re-run
the export against the results snapshot.

---

## Math, MDX gotchas

- Use `$...$` for inline and `$$...$$` for display math (KaTeX).
- Raw `{...}` in MDX is parsed as JSX — wrap LaTeX braces inside `$...$` or
  escape with `\{`.
- Code blocks are syntax-highlighted by Expressive Code (Starlight default).
