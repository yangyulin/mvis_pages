# Open MVIS — Project Site & Benchmark

Source for the [Open MVIS](https://openmvis.github.io) website: documentation
for the multi-visual-inertial sensor calibration toolbox, the open MVIS
datasets, and the public **calibration leaderboard**.

The site is built with [Astro 6](https://astro.build) and the
[Starlight](https://starlight.astro.build) docs theme. Static HTML is served
by GitHub Pages from `docs/`.

> **Vision.** Open MVIS aims to become the de-facto public benchmark for
> camera and visual-inertial sensor calibration over the next 10–20 years —
> the role KITTI plays for driving and Papers with Code plays for ML. See
> [`doc/PLAN.md`](doc/PLAN.md) for the roadmap and [`doc/DESIGN.md`](doc/DESIGN.md)
> for the architecture.

## Quick start (developing the site)

Prerequisites: Node 22 (via [nvm](https://github.com/nvm-sh/nvm) recommended).

```bash
nvm use 22                  # or `nvm install 22` first
cd site/
npm install
npm run dev                 # http://localhost:4321
```

Build the static site:

```bash
npm run build               # astro build into ../docs, then post-build.mjs renames _astro/ (Pages serves docs/)
npm run preview             # serve the built site locally
```

A build writes `docs/`, which GitHub Pages serves, so a build publishes the site once pushed.

## Generated data and the Python lib

Sensor pages, the results tables and the UZH-FPV table are generated by the Python lib in `python/mvis_site`
(see [`python/README.md`](python/README.md)). The scripts in `site/scripts/` only call it:

```bash
PYTHONNOUSERSITE=1 python3 site/scripts/export_sensors.py --private-config <mira sensors.yaml> --media <clips dir>
PYTHONNOUSERSITE=1 python3 site/scripts/export_uzh.py --leaderboard <mira leaderboard dir> --uzh-root <uzh study dir>   # e.g. ~/Project/openmvis-internal/results/datacard/uzh_fpv
PYTHONNOUSERSITE=1 python3 site/scripts/export_board.py --leaderboard <mira leaderboard dir> --records <snapshot> --results-commit <its full sha>
cd python && PYTHONNOUSERSITE=1 python3 -m pytest -q     # unit tests; python/cov.sh for coverage
```

Use a python whose numpy is < 2 (the anaconda base env); the export scripts refuse numpy 2.

What each writes:

| Script | Writes |
|---|---|
| `export_sensors.py` | `site/src/data/sensors/*.json`, `sensor.css`, `site/src/scripts/sensor-page.js`, `site/src/data/sensor-nav.json`, `site/src/content/docs/benchmark/sensors/*.mdx`, `site/public/media/sensors/<slug>/` |
| `export_board.py` | `site/src/data/leaderboard/board.json`, `board.css` |
| `export_uzh.py` | `site/src/data/leaderboard/uzh_fpv.json` |

The page text is public (`python/data/public_sensors.yaml`); the run paths stay private in mira and are passed by
path. Every sensor text drawn from the data (page JSON, MDX, process figures, sidebar) goes through a public lint
first; see `python/README.md` for the exact list. Edit the data or the lib, never the generated files.

Browser and media checks: `nav_check.py`, `responsive_check.py`, `hero_sync_check.py`, `hero_labels_check.py`
(Playwright with the system Chrome) and `check_hero_media.py` (ffprobe). Their rules are in `mvis_site/checks.py`.

## Adding content

### A new doc page

Create an MDX file under `site/src/content/docs/` matching the URL you want.
Example — `site/src/content/docs/calibration/my-page.mdx`:

```mdx
---
title: My Page
description: Short description used by search and social cards.
---

## Heading

Body content. Inline math: $f_x = 287.84$. Display math:

$$
\arg\min_{\boldsymbol{x}} \sum_i \rho(\|\mathbf{r}_i\|^2)
$$
```

Then add the page to the sidebar in `site/astro.config.mjs`.

### A new leaderboard entry

Drop a YAML file under `site/src/content/leaderboard/` following the schema
in [`doc/DESIGN.md` §6.1](doc/DESIGN.md#61-submission-schema-zod). The build
validates the schema; malformed entries fail the build.

The site shows the submission flow at `/leaderboard/submit/`.

---

## Math, MDX gotchas

- Use `$...$` for inline and `$$...$$` for display math (KaTeX).
- Raw `{...}` in MDX is parsed as JSX — wrap LaTeX braces inside `$...$` or
  escape with `\{`.
- Code blocks are syntax-highlighted by Expressive Code (Starlight default).
