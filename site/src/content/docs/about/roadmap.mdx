Use this page to see what we plan next for MVIS, the datasets, the benchmark and this site.

- **Intentions,** not commitments with dates
- **Each table** lists an item and its status
- **Not planned** lists what we will not do, and why

## Documentation

| Item | Status |
|---|---|
| Theory pages — full derivations and Jacobians | in progress; ported from `camera/CameraModel`, the unified factor, and the ACI / `t_ga` derivation (`t_ga` = time offset between the gyroscope and accelerometer channels) |
| **Generated** CLI reference | planned — [CLI](/reference/cli/) is hand-written and can drift |
| **Generated** configuration reference | planned — [Configuration](/reference/configuration/) is hand-written and can drift |
| Generated Python API from docstrings | undecided (**O4**) — [Python API](/reference/python-api/) is a hand-written map today |
| Simulation guide — authored trajectories | in progress; today's simulation is digital-twin only |

## Toolbox

| Item | Status |
|---|---|
| Continuous-time refinement | planned |
| Authored-trajectory synthetic generator | planned — would let us study degeneracy (when the motion leaves some parameters undetermined) without recording restricted motion |
| API stability guarantee | not yet — the CLI and config schema are the stable surface |
| `omni_radtan` out of experimental | in progress — already validated on TUM-VI camera–IMU |

## Not planned

- **Replacing Kalibr for single-IMU rigs.** Kalibr is mature and widely validated.
  MVIS exists for the multi-IMU, multi-model, no-ROS case. See
  [Comparison](/getting-started/comparison/).
- **A composite leaderboard score.** How to weight parameters against each other is
  the reader's judgement, not the benchmark's. See
  [Methodology](/benchmark/methodology/).
