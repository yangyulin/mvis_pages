## Toolbox

### 0.1.0 — first public release

The first public release of MVIS, the calibration toolbox behind this site.

- **Repository:** [`openmvis/openmvis`](https://github.com/openmvis/openmvis),
  package `pymvis` (CLI `mvis`), version 0.1.0.
- **Licence:** GPL-3.0-only, with a commercial licence for closed-source
  products. See [License](/about/license/).
- **Platforms:** Linux and macOS, Python 3.11 and 3.12. No Windows (GTSAM ships
  no Windows wheels).
- **Install:** `pip install pymvis` once the release is on PyPI; until then,
  from the repository. See [Installation](/getting-started/installation/).
- **What is in it:** camera-only and camera–IMU calibration for multi-camera,
  multi-IMU rigs (pinhole and omnidirectional models, `kb4` as the fisheye
  default, rolling shutter, `t_ga`, board shape), the digital-twin check, the
  simulator examples, HTML reports and the Kalibr camchain import and export.
  The regression suite that reproduces the benchmark tables stays with the
  maintainers; see [Regression testing](/contribute/regression-testing/).

## Documentation site

### Why calibrate: board shape and fisheye model (2026-11-11)

Two new pages in the Why calibrate section:
[board shape](/why/board-shape/) and [fisheye model (kb4)](/why/kb4/). The
overview, configuration reference and comparison now list all eight
distortion models, with `kb4` the fisheye default.

### Why calibrate section (2026-11-10)

A new section on what each calibrated quantity changes: [IMU](/why/imu/),
[t_ga](/why/tga/) (moved from `/benchmark/tga/`), [rolling shutter](/why/rolling-shutter/),
[multi-camera](/why/multi-camera/) and [multi-IMU](/why/multi-imu/).

### Leaderboard shows results, not scores (2026-11-03)

The leaderboard no longer gives scores or ranks. Each dataset now shows the
calibration results of MVIS, Kalibr and Basalt side by side. The differences
between them are shown too. See [Methodology](/benchmark/methodology/).

### Guide-site restructure

We reorganised the documentation from five sections into eight. It now follows a
tutorial / guide / concept / reference / example separation.
[Governance](/contribute/governance/) states the rule. Practical consequences:

- **Getting started** now separates Requirements, Installation, and Quickstart.
  Before, it was one Compilation page and a mixed Quick Start.
- **Guides** are task-oriented and no longer explain theory. Camera calibration,
  rolling shutter (the sensor reads the image row by row), multi-sensor rigs,
  and simulation each have their own page.
- **Concepts** collects the maths, with a shared
  [notation and glossary](/concepts/notation/).
- **Reference** holds the exhaustive material:
  - configuration
  - CLI
  - result formats
  - evaluation
  - datasets
- **Examples** became a per-dataset gallery. It includes validation against
  external references.
- **Old URLs** redirect. The legacy `openmvis.com/*.html` pages redirect too.

### Initial Starlight site

We migrated from jemdoc to Astro + Starlight. The first site brought:

- KaTeX maths
- search
- dark mode
- edit-this-page links
- the first leaderboard prototype
