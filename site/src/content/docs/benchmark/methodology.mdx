What the [leaderboard](/benchmark/leaderboard/) numbers mean and how they are
produced. The metric definitions are shared with
[Evaluation & metrics](/reference/evaluation/), so a local run and a published
entry measure the same thing.

## What the board shows

There is one table per dataset, grouped by regression family and then by sensor. MVIS, Kalibr and Basalt each calibrate
the recordings of a rig, and each cell gives a parameter as median ± sd (n) across the recordings that tool solved.
The board gives no scores or ranks: a single number would encode a judgement about which parameters matter.

:::caution[Differences are not errors]
These datasets have no metrological ground truth. A difference shows that two tools disagree, not which one is right,
and a small spread shows repeatability, not accuracy: a method can repeat the same bias on every recording.
MVIS checks accuracy separately, against known truth, in its digital-twin regression
([Regression testing](/contribute/regression-testing/)).
:::

## Differences

Each difference column subtracts the medians of two tools. A ◆ marks a difference larger than the larger of the two
spreads.

No difference is shown where it would mislead: values a tool takes as input, values shown only, missing values, and
rows where the tools' models differ. Reprojection error isn't compared, because it measures fit.

## Values that aren't estimates

| Label | Meaning |
|---|---|
| `fixed` | Kalibr's camera + IMU runs take this value as input, for example intrinsics |
| `shown` | The tool estimated it with a different model, so there's no difference against it |
| `no run` or `not run` | The tool has no result here, and the family's notes give the reason |
| `(3/15)` | The tool solved only 3 of the family's 15 recordings |

## Known limits

- MVIS rows and the Kalibr and Basalt runs were not all made on the same date. Data settings differ on T6, T7 and T8.
- Recording counts differ per tool on some families, so a difference can mix recording sets. These cells are marked.
- The MVIS column uses Kalibr's IMU model on camera + IMU families, so the IMU rows share one model. The MVIS default
  fills fewer rows and is in a closed fold under each family.

## Configs

Each family on the leaderboard links to the configs behind it, per tool. They're kept with the records in
[`calibench-vi/results`](https://huggingface.co/datasets/calibench-vi/results/tree/main/configs), and the README there
explains the files.

## Versioning

Each batch is dated and kept in the history of
[`calibench-vi/results`](https://huggingface.co/datasets/calibench-vi/results), so a comparison can be cited as
"Open MVIS leaderboard, batch 2026-11-02b, accessed &lt;date&gt;".
