MVIS is an open-source Python toolbox for camera and camera–IMU calibration. It
handles rigs with several cameras and several IMUs. An IMU (inertial
measurement unit) is the sensor with a gyroscope and an accelerometer.

- **Package:** `pymvis`. You import it as `mvis` and run it as the `mvis` command.
- **Built on:** [GTSAM](https://github.com/borglab/gtsam) factor graphs. A
  factor graph writes the whole calibration as one least-squares problem over
  linked unknowns.
- **Runs on:** Linux and macOS, Python 3.11 and 3.12, with no ROS install.
  See [Requirements](/getting-started/requirements/).
- **Code:** [github.com/openmvis/openmvis](https://github.com/openmvis/openmvis).

OpenMVIS, the project around MVIS, also publishes calibration
[datasets](/datasets/), a [benchmark](/benchmark/results/) against Kalibr and
Basalt, and a [device wiki](/devices/) of calibrated sensors.

## What it solves

MVIS solves the quantities below from one recording, in a camera solve and
then a camera–IMU solve.

| Quantity | Scope | Notes |
|---|---|---|
| Camera intrinsics + distortion | per camera | Focal length, image centre and lens model. Eight models, mixable in one rig ([Camera model](/concepts/camera-model/)) |
| Camera extrinsics | per camera | Where each camera sits relative to the reference camera |
| Camera–camera time offset | per camera | For cameras that are not hardware-synced |
| Rolling-shutter readout | per rolling-shutter camera | The time the camera takes to read its rows, top to bottom ([why](/why/rolling-shutter/)) |
| Board poses and board shape | per frame / per corner | The shape is one height per corner, off by default ([why](/why/board-shape/)) |
| Camera–IMU extrinsics `T_CtoI` and time offset `td` | per camera | |
| IMU–IMU extrinsics and time offset | per auxiliary IMU | Each extra IMU relative to the base IMU, the first IMU in the config |
| IMU intrinsics `Dw`, `Da`, optional `Tg` | per IMU | Gyro and accel scale and misalignment, in one of three conventions ([IMU model](/concepts/imu-model/)) |
| IMU biases | per IMU | |
| Gyro–accel time offset `t_ga` | per IMU (not gyro-only IMUs) | The delay between the gyro and accel channels of one IMU, on by default ([why](/why/tga/)) |

Several of these have no counterpart in Kalibr or Basalt. The
[comparison](/getting-started/comparison/) lists them.

## How a run works

A calibration has two solves and a check.

1. **Cameras:** `mvis cam` solves each camera's lens and the camera–camera
   extrinsics from a board recording. It writes a camera YAML and an HTML
   report.
2. **Cameras + IMUs:** `mvis cam-imu` reads that camera YAML as its starting
   point and solves the camera–IMU extrinsics, time offsets and IMU
   intrinsics. It writes a JSON result, a calibration YAML, a Kalibr
   camchain where the camera model allows, and an HTML report.
3. **Check:** `mvis verdict` grades a result GREEN, YELLOW or RED.
   `mvis roundtrip` applies a camera–IMU calibration to its own recording and
   calibrates again: the IMU intrinsics must come back as identity and the
   geometry must not move. A [digital twin](/guides/simulation/) of your rig
   tells you what the recording can pin down before you trust it.

`mvis run` starts either solve from the config's `mode:` field. Every command
is in the [CLI reference](/reference/cli/).

Inside the camera solve, the steps are:

1. **Detection:** find the board corners in every image.
2. **Quality gating:** drop frames with too few tags and corners seen too
   rarely.
3. **Init:** a first guess of each lens and each board pose.
4. **Per-camera solve:** refine each camera on its own, with its
   rolling-shutter readout if it has one.
5. **Alignment:** find where the cameras sit relative to each other, and
   their time offsets.
6. **Joint solve:** refine all cameras together.
7. **Outlier rerun:** drop corners with large error and solve again.

The camera–IMU solve starts from the camera YAML, picks the part of the
recording with the most motion and runs one joint solve with the IMU data.

You can also start from an existing calibration, such as Kalibr output, and
pin what you trust. See [Configuration](/reference/configuration/).
