Use this page to run your first calibration. The whole loop is three steps:

1. Write one YAML config file.
2. Run one command.
3. Read the HTML report.

Everything else in these docs is a variation on this loop.

You need:

- **MVIS installed:** see [Installation](/getting-started/installation/)
- **Images of an AprilGrid board:** a printed grid of AprilTag markers (square
  codes the software finds in each image)

## 1. Write the config

Save this as `config.yaml`. Point `source_path` at your images:

```yaml title="config.yaml"
board:
  board_type: apriltag          # or chessboard
  rows: 6
  cols: 6
  tag_size: 0.088               # metres
  tag_spacing: 0.3              # gap as a fraction of tag_size
  tag_family: t36h11

cameras:
  - camera_id: 0
    source_type: images         # or rosbag_topic, euroc, ros2bag
    source_path: /path/to/images
    distortion_model: radtan    # or equidistant, double_sphere, eucm, fov
    shutter_type: global        # rolling enables readout calibration

optimizer:
  max_iterations: 15
  pixel_sigma: 1.0
  huber_threshold: 1.345

output_file: calibration_result.yaml
```

:::caution[Measure the printed board]
`tag_size` is in metres. It must match the board you actually printed.
Measure a tag with calipers; do not trust the generator.
It sets the scale of every distance MVIS reports.
:::

## 2. Run it

```bash
mvis calibrate --config config.yaml
```

The pipeline runs seven stages, and prints progress as it goes:

1. Detection
2. Quality gating
3. Per-camera init
4. Per-camera refinement
5. Alignment
6. Joint optimisation
7. An outlier-driven rerun

## 3. Read the result

MVIS writes two YAML files, on purpose:

| File | Use |
|---|---|
| `*_calib.yaml` | The calibration itself — deploy this |
| `*_full.yaml` | Adds board poses, so a run can be replayed |

It also writes a **self-contained HTML report**. It is one file you can send to
someone. It holds:

- **Intrinsics and distortion tables:** the lens and sensor parameters of each camera
- **Extrinsics with a 3D plot:** where each camera sits
- **Reprojection error per frame and per tag:** how far, in pixels, the model's
  corners fall from the detected ones
- **Corner heatmaps:** the mean error at each corner of the board
- **Motion-excitation grades:** whether the recording moved enough to pin down
  each parameter
- **Detection statistics**

Open the report. Check the **motion-excitation grade** first, not the
reprojection error. A calibration can fit its observations tightly and still
have parameters that the recording never constrained.

## 4. Try a better model

`radtan` is a safe default, but not the best fit for every lens. For a fisheye
(very wide-angle) lens, start with `kb4`:

```yaml title="config.yaml"
    distortion_model: kb4
```

Eight models are available, and they are not interchangeable.
[Camera model](/concepts/camera-model/) says which to pick and how to tell when
one has diverged.
