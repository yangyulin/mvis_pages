Use this page to give us a calibration recording of your rig. A rig we have not
seen is worth more than another run on one we have. We credit every dataset we
host.

The steps:

1. Check that it is usable.
2. Package it in a format MVIS reads.
3. Write a dataset card.
4. Choose the licence.
5. Send it.

## 1. Check that it is usable

We can only calibrate from a recording that has:

- **Raw sensor streams:** no rectified (pre-undistorted) images and no
  vendor-corrected IMU output. The IMU (inertial measurement unit) is the
  gyroscope and accelerometer. A correction we cannot undo hides the intrinsics,
  the sensor's own parameters, so they cannot be calibrated.
- **A calibration board in view** for most of the recording. MVIS reads
  AprilGrid, chessboard and ArUco boards. See [Set up the board](/guides/board-setup/).
- **Motion on every axis:** rotation about all three axes and translation along
  them, not just one kind. See [Record the dataset](/guides/calibration-motion/)
  and [Degeneracy](/concepts/degeneracy/).
- **Timestamps from one clock** for all streams, or a stated offset between
  clocks.

Run `mvis inspect <path>` on your recording before you send it. It reports
which MVIS modes can read it, each camera stream (rate, resolution, encoding),
each IMU stream (rate, units, timestamp order) and how long the camera and IMU
streams overlap.

## 2. Package it

MVIS reads these inputs. Pick one that fits what you recorded:

- **ROS1 bag:** `Image` messages, or PNG or JPEG `CompressedImage`. Reading it
  needs no ROS install.
- **ROS2 bag.**
- **EuRoC / ASL folder:** the `mav0` layout used by EuRoC and TUM-VI.
- **Image folder, or timestamped images:** camera only. These carry no IMU
  data, so use one of the formats above for a camera–IMU recording.

`mvis inspect` lists the modes (`cam`, `cam-imu`) that can read your
recording.

[Configuration](/reference/configuration/) lists the input fields for each.

MVIS does not read video files. Convert video to images first.

Send these details with the data:

| Item | What to give |
|---|---|
| Board | type, rows and columns, tag or square size in metres, tag spacing, tag family |
| Sensors | model, rate, resolution and topic of each camera and IMU |
| Shutter | global or rolling for each camera; for rolling shutter, the readout direction if you know it |
| Timing | hardware-synchronised or not, and how timestamps are taken |
| Reference | any existing calibration, and the tool that produced it |

Send a reference calibration even if it is rough, and say how you got it. Then a
method can be checked against your recording, not only run on it.

## 3. Write a dataset card

Add one short page (a `README.md`) next to the data:

- **Rig:** what it is and what makes it different.
- **Recording:** how and where you recorded it.
- **Known problems:** dropped frames, clock jumps, saturated IMU segments,
  streams synchronised in software.
- **Licence:** the licence, and how to cite the data.
- **Contact:** who answers questions about it.

:::note[Say what is wrong with it]
The known-problems section matters most. A documented flaw leaves a usable
dataset. An undocumented one gives results nobody can explain, and every later
user repeats the same debugging.
:::

## 4. Licence

The licence must let us publish results computed on the data. For us to host a
copy, it must also allow redistribution.

- **Hosted by us:** recordings we host in the Hugging Face dataset
  [`calibench-vi/community`](https://huggingface.co/datasets/calibench-vi/community)
  use CC BY-NC 4.0 (non-commercial, attribution required). Downloads need a free
  Hugging Face login with automatic approval.
- **Hosted by you:** if your data must stay under another licence, keep it where
  it is. We add a download recipe that points to your copy.
- **People and private spaces:** blur faces, screens, documents and anything
  else private before you send the data. We do not publish recordings that
  still show them.
- **Your rights:** you must own the data or have the right to grant the licence.

## 5. Send it

Open an issue on [`openmvis/mvis_pages`](https://github.com/openmvis/mvis_pages/issues).
In it:

- describe the rig in one or two sentences
- link the data (any download link works)
- attach or link the dataset card

We reply on the issue and arrange hosting from there. Data we host ends up in
[`calibench-vi/community`](https://huggingface.co/datasets/calibench-vi/community);
open the request on the issue tracker, not there.

## Credit

We credit every dataset we host. What that includes is listed in
[Governance › Credit](/contribute/governance/#credit). To send results on an
existing dataset instead, see [Submit results](/contribute/submit-results/).
