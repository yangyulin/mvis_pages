:::caution[Submissions are paused]
Submissions are not being accepted while this process is replaced by a new kit. The format below is the old one.
Entries in it will not appear on the [leaderboard](/benchmark/results/). The leaderboard is built from the
maintainers' runs of MVIS, Kalibr and Basalt.
:::

Use this page to submit your calibration method to the Open MVIS leaderboard. In short:

- **How:** open a pull request (PR, a request to merge your change) against the Open MVIS site repo.
- **What:** add a single YAML file that follows the schema below (the fixed set of fields a submission has).
- **Checks:** the CI on the PR (the checks that run automatically) validates the schema. It then rebuilds the
  site with your entry included.

## Submission schema

```yaml
# src/content/leaderboard/<method>__<config>.yaml
method:
  name: MVIS
  version: "0.4.2"
  family: discrete_factor_graph      # see families list below
  open_source: true
  url_repo: https://github.com/.../MVIS
  url_paper: https://arxiv.org/abs/...
sensor_config:
  category: multi_imu_multi_cam      # one of 7 categories
  num_imus: 4
  num_cams: 4
  imus: [MicroStrain GX3-25, GX3-35, Xsens MTI-100, RealSense T265]
  cameras: [BlackFly, T265-L, T265-R, ELP-L]
dataset:
  name: open_mvis_4imu4cam
  version: v1.0
  sequences: [4imus_4cams_01, 4imus_4cams_02, 4imus_4cams_03]
results:
  reprojection_rmse_px:    {value: 0.41, stddev: 0.03, n_runs: 5}
  extrinsic_rot_err_deg:   {value: 0.08, stddev: 0.02, n_runs: 5}
  extrinsic_trans_err_cm:  {value: 0.12, stddev: 0.04, n_runs: 5}
  timeoffset_err_ms:       {value: 0.31, stddev: 0.05, n_runs: 5}
  runtime_s:               {value: 142,  stddev: 8,    n_runs: 5}
  convergence_rate_pct:    100
artifacts:
  report_html: reports/mvis__open_mvis_4imu4cam.html
  raw_yaml:    raw/mvis__open_mvis_4imu4cam.yaml
submitted:
  by: Your Name
  date: 2026-04-20
  hardware: AMD 7950X, 64 GB RAM, no GPU
```

## Category values

Use one of these `sensor_config.category` values:

- `cam_only_mono`
- `cam_only_stereo`
- `cam_only_multi`
- `single_imu_single_cam`
- `single_imu_multi_cam`
- `multi_imu_single_cam`
- `multi_imu_multi_cam`

## Family values

Use one of these `method.family` values:

| Value | Meaning |
|---|---|
| `discrete_factor_graph` | GTSAM / Ceres batch MAP (all data solved at once for the most likely values) |
| `continuous_time_bspline` | SE(3) B-splines (smooth curves of the pose over time; Kalibr, Basalt) |
| `filter_ekf` | online EKF (an extended Kalman filter that updates as data arrives; OpenVINS-style) |
| `learning_based` | deep-network regression |
| `other` | hybrid or none of the above |

## Filing the PR

1. Fork [`yangyulin/mvis_pages`](https://github.com/yangyulin/mvis_pages) on GitHub.
2. Drop your YAML at `site/src/content/leaderboard/<method>__<config>.yaml`.
3. (Optional) Add a full HTML report and raw YAML at `site/public/reports/`. Reference them in the
   `artifacts` block.
4. Open a PR. The schema is validated on build, and the CI preview will show the new row immediately.
5. A maintainer will merge once the schema passes and the numbers look reasonable.

## Reproducibility expectation

For external submissions we expect one of these:

- A public repo where anyone can reproduce your numbers, **or**
- A paper citation whose experimental protocol matches the submission, **or**
- Both.

## Verification

For now, submissions are self-reported. The `submitted.by` and `submitted.hardware` fields carry the
accountability trail: who submitted and on what hardware.

A future version of the leaderboard will offer server-side evaluation (results computed on the server, not reported by you). It
will run on hidden ground-truth sequences (recordings whose true values are not published). This is the model
used by the Hilti SLAM Challenge.
