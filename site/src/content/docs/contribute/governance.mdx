Use this page to know what to expect before you spend effort on a
contribution. It covers:

- **Maintainers:** who runs the project
- **Review:** how each kind of submission is checked
- **Rules:** documentation, conduct, credit and licence

## Maintainers

The [Robot Perception and Navigation Group
(RPNG)](https://sites.udel.edu/robot/) at the University of Delaware maintains
Open MVIS. [Contributors](/about/contributors/) lists the current maintainers.

## Review process

Each kind of submission is reviewed for different things:

| Submission | Reviewed for | Turnaround |
|---|---|---|
| Leaderboard result | Schema validity, plausible values, complete provenance | *to be set* |
| Dataset | Format, dataset card, licence, usability | *to be set* |
| Documentation | Accuracy, page-type fit (see below) | *to be set* |
| Code | Correctness, tests, no regression | *to be set* |

CI (continuous integration, the checks that run automatically) validates what it
can:
schema, bounds and build. A maintainer reviews what it cannot.

## Verified results

Each result on the [leaderboard](/benchmark/results/) is one of two kinds:

| Kind | Meaning | Badge |
|---|---|---|
| **Reported** | A result as submitted | No |
| **Verified** | A maintainer has re-run it from the submitter's configuration and data | Yes |

We verify where possible, but do not require it. Verification depends on the
data being available and the run being tractable.

We keep the difference visible on purpose. If reported and reproduced numbers
cannot be told apart, nobody should trust the leaderboard.

## Documentation rule

Each page on this site declares a `pageType` and is held to it:

| Type | Contains | Does not contain |
|---|---|---|
| `tutorial` | One ordered happy path | Alternatives, options, theory |
| `guide` | Task-oriented steps | Derivations — link to a concept |
| `concept` | Explanation, maths, figures | Commands — link to a guide |
| `reference` | Exhaustive, anchor-per-entry | Narrative |
| `example` | A real run with validation | Concepts introduced for the first time |

When a page drifts, split it; do not blend the two types:

- **A guide that starts explaining** means a concept page is missing.
- **A concept page that starts instructing** means a guide is missing.

Documentation pull requests are reviewed against this rule.

## Conduct

Be civil and assume good faith. We do not tolerate:

- harassment
- personal attacks
- deliberate bad-faith submissions

Maintainers may reject submissions and restrict participation. Report problems
to the maintainer contacts on [Contributors](/about/contributors/).

## Credit

- **Leaderboard entries** are attributed to their submitter.
- **Datasets** get a DOI, a citation, and named credit.
- **Substantial contributions** to a dataset or benchmark release are
  recognised with co-authorship on the corresponding paper.

## Licence

The toolbox and the site are open source — see [License](/about/license/).
Contributions are accepted under the same licence.
