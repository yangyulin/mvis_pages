Step 1 of the walkthrough. Here you pick a board, measure it and describe it to MVIS.

- **You need:** a printed board, or a monitor to show one on.
- **You get:** a `board:` block for your config. [Step 2](/guides/calibration-motion/) records with this board,
  and [step 3](/guides/camera-calibration/) puts the block in its config.
- **Check:** the tag or square size in the block matches what you measured on the board.

:::note[Running example]
Every guide step uses the same rig: the VI-Rig recording set
[virig-4imus-4cams](/datasets/virig-4imus-4cams/). It has 4 IMUs, a RealSense T265 fisheye pair and an
ELP stereo pair. You can download it from the Calibench Hub (`calibench-vi/datasets`). Access is gated, and the
licence is CC BY-NC 4.0 (for commercial use, ask us).
:::

We recorded the [calibration motion](/guides/calibration-motion/) with these two boards. You can download
both as images with configs in [section 5](#5-no-printer-use-a-screen-board). Each board type needs these
fields:

| Board | `board_type` | Required fields |
|---|---|---|
| AprilGrid | `apriltag` | `rows`, `cols`, `tag_size` (m), `tag_spacing` (gap ÷ tag size), `tag_family` |
| Chessboard | `chessboard` | `rows`, `cols` (**inner corners**), `square_size` (m) |

- **Which to pick:** an AprilGrid still gives corners when part of it is out of view. A chessboard has to be
  fully in view.
- **AprilGrid tags:** `tag_family: t36h11` is the Kalibr AprilGrid, which has a 2-bit black border round each
  tag. Use `t36h11b1` for standard AprilTag 3 tags, which have a 1-bit border.
- **ArUco boards** also work (`board_type: aruco`). See [Configuration](/reference/configuration/).
- **A Kalibr target file:** no config key reads one. Copy its values into the `board:` block, as in section 2.

## 2. The board in the running example

The VI-Rig recordings use a printed AprilGrid:

- **Grid:** 6 × 6 tags, family t36h11.
- **Tag:** 0.088 m, edge to edge.
- **Spacing:** 0.3, the gap between tags divided by the tag size.

Its Kalibr target file, `april.yaml`, sits next to the bags on the Hub. It reads `target_type: 'aprilgrid'`,
`tagCols: 6`, `tagRows: 6`, `tagSize: 0.088`, `tagSpacing: 0.3`.

The same board in MVIS:

```yaml title="config.yaml"
board:
  board_type: apriltag
  rows: 6
  cols: 6
  tag_size: 0.088
  tag_spacing: 0.3
  tag_family: t36h11
```

## 3. Measure what you printed

:::caution[Measure the printed board]
Print at 100 % and measure one tag with calipers. If it differs from `tag_size`, every translation in the
rig scales by the same factor. No residual shows this error.
:::

## 4. A board is never flat

A printed board bends and twists a little. A solve that takes it as flat pushes that error into the
calibration.

We estimated the shape of the VI-Rig board from the camera residuals:

- **Size of the bend:** 10–11 mm peak to peak, 2.3–2.4 mm rms, on the mount we used. A different mount gives
  a different shape.
- **One run:** the [4 IMUs + 4 cameras example](/benchmark/examples/virig-4imus-4cams/) estimates it at
  2.21 mm rms and 8.94 mm peak to peak.
- **Effect:** the camera-only residual drops and the focal length moves. The numbers are in
  [Why calibrate the board shape](/why/board-shape/).

Turn it on with one key. MVIS then solves one height per board corner, in camera-only and camera–IMU runs:

```yaml title="config.yaml"
board:
  # ... the fields above ...
  heights_file: board_shape_4imus_4cams.yaml   # optional start values (camera–IMU runs only)
estimate:
  board_points: true
```

- **`estimate.board_points: true`:** solves the board shape together with everything else. It is off by
  default. We turn it on for every VI-Rig solve.
- **`board.heights_file`:** optional start values for the heights. Only camera–IMU runs read it. Without it
  the heights start flat.
- **Where a heights file comes from:** a camera–IMU run with `board_points: true` writes
  `<output>_board_shape.yaml` next to its output. The example's `board_shape_4imus_4cams.yaml` is such a file.
- **Prior:** each height has a weak prior of 3 mm, so a corner the cameras never saw stays near its start. In
  camera–IMU runs you can change it with `solve.board_height_sigma` (in m). Camera-only runs keep 3 mm.
- **One board only:** a camera–IMU run with several boards cannot estimate the shape.

## 5. No printer? Use a screen board

You can show the board on a monitor. We made two full-screen images for a 2560 × 1440 monitor, with configs
for MVIS and Kalibr:

| Board | Size | Downloads |
|---|---|---|
| AprilGrid 6 × 6 | tag36h11, tag 43.47 mm, spacing 0.3 | [image](/downloads/boards/aprilgrid_6x6_2560x1440.png) (PNG, 75 KB) · [MVIS config](/downloads/boards/aprilgrid_6x6_mvis.yaml) · [Kalibr config](/downloads/boards/aprilgrid_6x6_kalibr.yaml) |
| Chessboard 10 × 7 squares | 9 × 6 inner corners, square 43.47 mm | [image](/downloads/boards/chessboard_10x7_2560x1440.png) (PNG, 30 KB) · [MVIS config](/downloads/boards/chessboard_10x7_2560x1440_mvis.yaml) · [Kalibr config](/downloads/boards/chessboard_10x7_2560x1440_kalibr.yaml) |

**How to show them:**

1. Open the image full screen at 100 % on a 2560 × 1440 monitor.
2. Turn off display scaling and zoom, so one image pixel is one screen pixel.
3. Measure one tag or square with a ruler. On our monitor, 160 px (one tag or one square) is 43.47 mm, the
   size in the configs.
4. If yours differs, put your size in the config:
   - **MVIS:** `tag_size` or `square_size`.
   - **Kalibr:** `tagSize`, or `rowSpacingMeters` and `colSpacingMeters`.

**Setup:**

- Keep the screen upright and still.
- Use enough light for a short exposure (about 2 ms), so the corners do not blur.
