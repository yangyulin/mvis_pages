Use this page to test the solver on a copy of your rig where the truth is known.
You need the cam-IMU config and bag from
[step 4](/guides/camera-imu-calibration/). You get the error of each parameter
against the truth.

A **digital twin** is a simulated copy of your recording:

- **The truth** is your real solve, moved off by a small seeded perturbation:
  calibration, board pose and shape, biases and trajectory. The perturbation
  makes the solve recover values it was not given. It also keeps your real
  calibration out of a saved twin. `perturb_seed=None` in `capture` keeps the
  real solve as it is.
- **The timing** is real: MVIS keeps the real frame times, the corner ids seen
  in each frame and the IMU stamps.
- **The data** is new: MVIS regenerates the corners and the IMU from the truth,
  with rolling shutter and t_ga (the time offset between gyroscope and
  accelerometer).
- **The solve** is the real pipeline, run again on the new data.

So any gap between the result and the truth comes from the solver, not from the
recording.

## 1. Build and solve a twin

The twin lives in the Python module `mvis.simulation.twin`.

```python title="twin.py"
from mvis.simulation import twin

# Runs the real solve (it needs the bag) and takes it as the truth.
# noise_from_residuals sets the noise to match the real residuals.
tw = twin.capture("virig_4imus_4cams_cam_imu.yaml", "virig4",
                  noise_from_residuals=True)

report = twin.solve(tw, seed=0)              # with noise
clean = twin.solve(tw, noise=False)          # noise-free

tw.save("virig4_twin.npz")                   # keep it; no images inside
tw = twin.Twin.load("virig4_twin.npz")
```

- **`capture`** runs your cam-IMU config once, on the real bag.
- **`solve`** simulates, solves and returns the errors (estimate minus truth).
- **`seed`** picks the noise draw. Run a few seeds, not one.
- **A saved twin** needs no bag. Solve it again after any code change.

:::caution[What the twin does not test]
The simulated noise is Gaussian. There are no lens or timing model errors. So
the twin checks the estimator, not the recording.
:::

## 2. Read the errors

Each solve returns, per sensor:

- **Cameras:** lever arm (mm), rotation as a log(R) vector (mrad), td (the
  camera–IMU time offset, ms), readout (ms), focal length (px).
- **Base IMU:** t_ga (ms), gyro and accelerometer scale (%).
- **Each auxiliary IMU:** lever, rotation, td, t_ga and scales.
- **Board:** rms height error (mm), when the board shape is estimated.

Read the two runs side by side:

- **Noise-free error** should be near zero. If not, the solver does not recover
  the truth, even from perfect data. That is a model or observability problem.
- **Seed error** (with noise) shows what your data can support. Large seed error
  with small noise-free error means the data limits the result, not the solver.
- **The IMU noise is a rough match.** It is scaled from the solver's IMU
  chi2, which reads low. So seed errors of IMU-driven parameters may be
  optimistic.

This video twin is built straight from the solve, with fixed noise. It differs from the
`twin` module of section 1:

- **Truth:** the real solve as it is (no perturbation): trajectory, board, every camera and IMU.
- **Cameras:** all four at 30 Hz, each seeing every tag in its view, with 0.5 px corner noise.

So the twin's corners are cleaner than the real ones: on real data the per-frame RMS jumps when the

## 4. Running example: VI-Rig ELP pair

We built a twin of the ELP-pair cam-IMU row on
[virig-4imus-4cams](/reference/datasets/virig-4imus-4cams/) bag 01:

- **Cameras:** ELP left and right, rolling shutter.
- **IMUs:** T265 IMU as the base, Xsens as the auxiliary IMU.
- **Settings:** the same row as T8 in the
  [results](/benchmark/results/virig-4imus-4cams/): camera intrinsics free,
  t_ga on, board shape on.

Errors against the truth (estimate minus truth). Lever and rotation are the length of the 3D
error; a scale is the largest of its three axis errors.

| Parameter | Noise-free | With noise, RMS over seeds 0–2 (upper bound) |
|---|---|---|
| Camera lever | 0.094 mm | 1.67 mm |
| Camera rotation | 0.177 mrad | 2.35 mrad |
| Camera td | 0.007 ms | 0.15 ms |
| Camera readout | 0.003 ms | 0.23 ms |
| Camera focal length | 0.009 px | 0.22 px |
| Base t_ga | 0.015 ms | 0.47 ms |
| Base gyro scale | 0.011 % | 1.22 % |
| Base accel scale | 0.013 % | 0.28 % |
| Board height rms | 0.23 mm | 0.22 mm |
| Aux lever | 0.164 mm | 2.46 mm |
| Aux rotation | 0.245 mrad | 3.56 mrad |
| Aux td | 0.007 ms | 0.56 ms |

Camera rows are ELP left; ELP right is close. What it shows:

- **The solver converges to the truth.** Without noise every error is a fraction of a mm, mrad or
  ms, and scales land within 0.02 %. This is the check that matters.
- **The noisy column is an upper bound.** The twin's IMU noise is set from the real IMU fit, but
  that fit is scored with t_ga forced to 0. On this row the base IMU is the T265, with t_ga
  about −6.7 ms, so the twin gets more IMU noise than the real sensor has. The real spread over
  the 15 recordings is much smaller: T265 gyro scale 0.03–0.13 % per axis, t_ga 0.13 ms, ELP
  readout 0.12 ms ([results](/benchmark/results/virig-4imus-4cams/), family T8). A fix is in
  progress.
- **The board height** keeps about 0.2 mm error even without noise.

We keep these numbers as a reference. A new MVIS version fails the check if an
error grows past the reference by more than:

| Quantity | Allowed growth (noise-free) |
|---|---|
| Lever | 0.2 mm |
| Rotation | 0.2 mrad |
| td, readout | 0.05 ms |
| t_ga | 0.1 ms |
| Gyro scale | 0.01 % |
| Accel scale | 0.02 % |
| Focal length | 0.2 px |
| Board height rms | 0.1 mm |

Seed errors may grow by twice these amounts, as three seeds are a rough sample.
A solve that fails or takes no step also fails the check. Smaller errors never
fail.

## Without ground truth

On real data there is no truth. We have two substitutes, strongest first:

1. **[Round-trip](/guides/roundtrip/)**: `mvis roundtrip` applies the
   calibration to its own bag and recalibrates. PASS requires IMU intrinsics to
   collapse *and* geometry to hold.
2. **Repeatability**: run a
   [batch sweep](/guides/camera-imu-calibration/#batch-a-whole-dataset-family-from-one-config)
   across sequences of the same rig. Parameters that move between sequences
   were not constrained by the motion in them.

## Motions you have not recorded

The twin replays a motion you recorded. To try a new motion, MVIS also has
`mvis.simulation.scenario`:

- It bundles a trajectory, a true calibration and a board placed in the world.
- It generates camera corners, a base IMU and an optional auxiliary IMU, with
  full truth.
- One trajectory ships with the package (`sine_3d`).

This is a lower-level tool than the twin. For the theory of weak motions, see
[Degeneracy](/concepts/degeneracy/).
