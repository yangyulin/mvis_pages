Use this page to calibrate one or more cameras without an IMU. MVIS solves all
of these jointly:

- **Intrinsics:** focal length and image centre of each camera
- **Distortion:** how the lens bends straight lines
- **Extrinsics:** where each camera sits relative to the others
- **Time offsets:** the clock delay between cameras
- **Rolling-shutter readout:** the time a rolling-shutter sensor takes to read
  out one frame, row by row

This is also **step one of camera–IMU calibration**. That step uses the result
of this one.

## 1. Make a target

<Image src={kalibrBoard} alt="AprilGrid target" width="200" />
<Image src={aurcoBoard} alt="ArUco target" width="200" />

Pick one of three boards. Each needs these fields in the config:

| Board | `board_type` | Required fields |
|---|---|---|
| AprilGrid | `apriltag` | `rows`, `cols`, `tag_size` (m), `tag_spacing` (ratio), `tag_family` |
| Chessboard | `chessboard` | `rows`, `cols` (**inner corners**), `square_size` (m) |
| ArUco | `aruco` | `rows`, `cols`, `marker_size`, `marker_separation`, `aruco_dict` |

AprilGrid follows the Kalibr 2-bit border convention. Kalibr target YAMLs load
directly via `apriltag_board.from_kalibr_yaml`.

:::caution[Measure the printed board]
Print at 100% and measure a tag with calipers. If the true size differs from
`tag_size`, every translation in the rig scales by that same factor. This error
is silent and systematic: no residual will reveal it.
:::

## 2. Record

- **Fill the frame** and cover the image out to its corners. Distortion is only
  constrained where tags were actually seen.
- **Vary distance and angle.**
- **Avoid motion blur.**

## 3. Point the config at your data

MVIS reads six input formats. All of them stream one image at a time, so memory
stays bounded whatever the dataset size.

A folder of images:

```yaml title="config.yaml"
cameras:
  - camera_id: 0
    source_type: images              # a folder, sorted by filename
    source_path: /path/to/cam0_images
```

A ROS1 bag, with several cameras from one bag:

```yaml title="config.yaml"
cameras:
  - camera_id: 0
    source_type: rosbag_topic        # ROS1 — several cameras from one bag
    source_path: /path/to/data.bag
    topic: /cam0/image_raw
  - camera_id: 1
    source_type: rosbag_topic
    source_path: /path/to/data.bag
    topic: /cam1/image_raw
```

A EuRoC / ASL folder, as used by TUM-VI and Monado SLAM:

```yaml title="config.yaml"
cameras:
  - camera_id: 0
    source_type: euroc               # EuRoC / ASL — TUM-VI, Monado SLAM
    source_path: /path/to/cam0
```

Also available:

- `timestamped_images`: a folder plus a CSV of timestamps
- `ros2bag`

## 4. Pick a distortion model

```yaml title="config.yaml"
    distortion_model: kb4            # radtan | kb4 | equidistant | fov
                                     # double_sphere | eucm | ucm | omni_radtan
```

- **Normal lenses:** `radtan`
- **Fisheye lenses:** `equidistant`
- **Mixed rigs:** models can be **mixed across cameras** in one rig

The trade-offs are in [Camera model](/concepts/camera-model/). That page also
covers the divergence to watch for with a wide field of view (FoV).

## 5. Run

```bash
mvis calibrate --config config.yaml
```

## What the pipeline does

The failure messages name these stages, so they are worth knowing:

| Stage | What happens |
|---|---|
| Detection | Adaptive multi-scale AprilTag — probes scale 1.0, then up to 2 adaptive scales by observed module size; subpixel refinement at original resolution |
| Quality gating | Corner subsample, pooled-pose filter (≥20% tags across cameras), per-corner ≥5 views, per-camera ≥3 views, ≥6 tags/frame |
| 1 | Per-camera init — vanishing-point focal + RANSAC PnP board poses + sanity check |
| 2 | Per-camera GTSAM refinement, with rolling-shutter readout if enabled |
| 3 | Trajectory alignment — extrinsics via RANSAC, time offsets via dual PnP + homography cross-correlation |
| 4 | Joint multi-camera factor graph — the unified factor, all parameters |
| 5 | Outlier-driven rerun with pathology guardrail |

## Speed

`corner_subsample` defaults to `top_left`. It uses one corner per tag instead of
four.

- **Speed-up:** **3–5× faster for under 0.1% quality drift**
- **Tested:** validated across eight dataset families
- **Fallback:** it switches to `all` on its own when the data is sparse

```yaml title="config.yaml"
corner_subsample: top_left     # top_left | two_diag | all
```

If a long recording is slowing you down, `factor_hz` subsamples the frames.

## 6. Read the report

MVIS writes three files:

- **`*_calib.yaml`:** the result to deploy
- **`*_full.yaml`:** the result plus board poses, to replay the run
- **HTML report:** self-contained

Check the **motion-excitation grade** before the reprojection error. The grade
says how well your motion constrained the calibration. The reprojection error
is the pixel gap between seen and predicted corners. See
[Evaluation & metrics](/reference/evaluation/).

## Multi-camera

1. Add one entry per camera to `cameras:`.
2. Set `reference_camera`.
3. For unsynchronised cameras, enable `optimize_time_offset: true`.

There is no separate stereo step. All cameras enter one graph. A five-camera rig
stays consistent this way, instead of piling up pairwise error.
