Use this page to check that a calibration is *right*, not only that it fits.

- **Reprojection error** (how far detected corners land from where the
  calibration predicts them) tells you a calibration fits its own observations.
  It does not tell you the calibration is right.
- **Round-trip** does. We apply the calibration to the data it came from, then
  calibrate again. If it was correct, there is nothing left to find.

```bash
mvis roundtrip -c cam_imu.yaml
```

One command runs four steps:

1. Calibrate.
2. Correct the data with [`apply-calib`](/guides/corrected-datasets/).
3. Recalibrate.
4. Report.

It exits non-zero on FAIL, so it belongs in CI.

## What PASS means

PASS needs two conditions. They pull in opposite directions, which is what
makes the test informative.

- **Collapse.** On the corrected bag, every IMU's `Dw` and `Da` (the gyroscope
  and accelerometer scale and axis-misalignment matrices) must go to identity.
  The biases `b_g` / `b_a` must go to zero. The first pass claimed to have
  measured those. If it was right, correction consumed them and there is
  nothing left.
- **Preserve.** The camera and IMU extrinsics (the poses between sensors) must
  not move. Nor must the **stereo baseline**. Correction changes timing and
  inertial scaling, not geometry. A baseline that shifts means the first solve
  traded geometry against something else.

Residual `td` (the camera-to-IMU time offset) is a **warning, not a failure**.
How much of a time offset survives correction depends on how observable it is.

## Flags

| Flag | Effect |
|---|---|
| `-c`, `--config` | The cam-IMU config to validate |
| `--out` | Report path |
| `--bag` | Override the config's bag |
| `--keep-corrected` | Keep the intermediate corrected bag |
| `--keep-bias` | Passed through to `apply-calib` |

The corrected bag gets a distinct name. So it gets a **fresh detection cache**
rather than silently reusing the original's. It is deleted afterwards unless
you keep it.

## Confirmed results

| Rig | Collapse | Preserve |
|---|---|---|
| virig 3cams | all four IMUs' `Da` → identity | baseline 69.86 mm stable |
| Monado / MIC05 | `Da` 1.06 → 1.00, `b_a` −0.25 → −0.01 | baseline 133.8 mm stable |

## When it fails

A FAIL is a real finding, not a flaky test. The usual causes:

- **Wrong camera model.** The intrinsics absorbed error that reappears once
  timing is corrected. Try another [distortion
  model](/concepts/camera-model/).
- **Wrong IMU convention.** See [IMU model](/concepts/imu-model/).
- **An interpolated accelerometer** corrupting `td`. This is the T265 case.
  The fix is `gyro_only` on that IMU, or estimating `t_ga` (the time offset
  between the gyroscope and accelerometer channels). A self round trip does
  not catch this case by itself: a tool with no `t_ga` also returns to about
  zero on its own corrected bag. Turn `t_ga` on and read it, or run a
  correlation check. See [Why calibrate t_ga](/benchmark/tga/).
- **Insufficient excitation.** The parameter was never observed, so
  correcting by it does nothing consistent.
