Use this page for an overview of the IMU maths. It shows how the inertial
factors carry the calibration state, and links to the two derivations.

The camera factor constrains geometry. (A factor is one term of the cost the
solver minimises.) The inertial factors carry the rig through the gaps between
images.

Both are written so that calibration parameters appear *inside* the residual
(the error a factor measures). They are not applied afterwards. That is what
lets the graph solve them.

This section splits along the same line the implementation does:

- **[Base IMU factor](/concepts/camera-imu-math/base-imu/)** — pre-integration
  (the IMU readings between two states combined into one relative motion) between
  consecutive states. The base IMU's own intrinsics (its internal sensor
  parameters) sit in the residual. The base IMU defines the trajectory, so its
  errors move everything.
- **[Auxiliary IMU factor](/concepts/camera-imu-math/aux-imu/)** — an
  auxiliary IMU observes the *same* motion through a rigid transform and a time
  offset. That redundancy is what makes the extra IMUs worth carrying. It is
  also what the factor encodes.

## Why calibration goes inside the factor

The naive alternative cannot work in a solver. That alternative is to integrate
the IMU, then correct the result using a calibration estimate. It fails because
the correction has no derivative with respect to the parameters being solved.

So we put these inside the pre-integration:

- $\mathbf{D}_w$, $\mathbf{D}_a$, $\mathbf{T}_g$
- the extrinsics (the transforms between sensors)
- the time offsets

Then each has a Jacobian (the derivative of the residual with respect to that
parameter), and the optimiser can move it.

The cost is that pre-integration is no longer a one-time operation. Changing an
intrinsic changes the integrated quantity. So the factor must expose how its
value responds.

Both derivation pages are structured the same way:

1. measurement model
2. residual
3. the Jacobian for every calibration variable it touches

## What each factor constrains

| Factor | Constrains directly | Constrains indirectly |
|---|---|---|
| Base IMU | biases, $\mathbf{D}_w$, $\mathbf{D}_a$, $\mathbf{T}_g$ | trajectory scale and gravity direction |
| Auxiliary IMU | ${}^{I}_{I_{s_j}}\mathbf{T}$, $t_{d,j}$, its own intrinsics | base-IMU intrinsics, via redundancy |
| Camera | intrinsics, ${}^{I}_{C_i}\mathbf{T}$, $t_{d,i}$, $t_{r,i}$ | trajectory in the board frame |

No single factor observes the whole state. Which parameters actually become
observable depends on the motion. That is the subject of
[Observability](/concepts/observability/).
