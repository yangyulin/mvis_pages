The [TUM Visual-Inertial dataset](https://cvg.cit.tum.de/data/datasets/visual-inertial-dataset)
is the standard external check for a camera–IMU calibrator: it ships a
stereo-fisheye + IMU rig *and* the authors' own calibration, so a run can be
scored against a reference someone else produced.

## The rig

| Sensor | Rate | Notes |
|---|---|---|
| 2 × monochrome global-shutter cameras | 20 Hz | 512×512, fisheye — equidistant model |
| Bosch BMI160 IMU | 200 Hz | accelerometer + gyroscope |

Use the dataset's **calibration sequences** (the `calib` bags), not the room or
corridor sequences — the latter are recorded for SLAM evaluation and do not hold
the board in view.

## Getting the data

Download a calibration sequence in ROS-bag form from the dataset page.

:::caution[Two preparation steps are required]
The bags need fixing before Open MVIS will read them:

1. **Pixel format** — images are stored as `mono16`; the front-end expects
   `mono8`. Convert with `bag_mono16_to_mono8.py`.
2. **Clock stamps** — camera and IMU headers need re-stamping onto a common
   clock, otherwise the solver sees an apparent time offset that is an artefact
   of the recording rather than the hardware.

Skipping either produces a run that converges to a wrong `td`.
:::

## Configuration

Fisheye cameras, so the equidistant model:

```xml title="launch/tum_vi.launch"
<param name="cam0_is_fisheye" type="bool" value="true" />
<param name="cam1_is_fisheye" type="bool" value="true" />
```

Seed the base IMU ↔ `cam0` transform from the dataset's published calibration —
this is the one parameter that needs a real starting point
([Camera–IMU calibration](/guides/camera-imu-calibration/), step 6).

## Running it

```bash
source devel/setup.bash
roslaunch mvis tum_vi.launch
```

## Result and validation

TUM VI publishes `T_cam_imu` for both cameras, which is exactly what this run
solves — so the comparison is direct: rotation difference in degrees,
translation difference in centimetres, per camera.
