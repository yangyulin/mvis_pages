Use this page to see what a run writes, and which file to use for what.

- **Camera calibration:** two YAML files, one to deploy and one to replay
- **Cam-IMU:** one JSON result, with fields per sensor
- **Report:** one self-contained HTML file per run
- **Kalibr:** read and write Kalibr files through `mvis.io.kalibr`

## Dual YAML — camera calibration

Camera calibration writes two files on purpose:

| File | Contains | Use for |
|---|---|---|
| `*_calib.yaml` | Intrinsics, distortion, extrinsics, time offsets, readout | **Deploy.** The calibration itself |
| `*_full.yaml` | The above **plus per-frame board poses** | **Replay.** Re-run analysis without redetecting |

Intrinsics are the camera's own projection parameters.
Extrinsics are the poses between sensors.
Readout is the rolling-shutter readout.

- **Deploy** the small one.
- **Keep** the full one to reproduce the run.

Both carry a `timings:` block. It holds hierarchical per-stage timings with metadata.
With it, you can ask whether a change was faster overall or only in one stage.

`output_format: json` writes JSON instead.

## Cam-IMU JSON

`mvis cam-imu` writes a JSON result containing, per sensor:

| Field | Meaning |
|---|---|
| `T_CtoI` | Camera → IMU transform |
| `td` | Camera–IMU time offset |
| readout | Rolling-shutter readout, when estimated |
| `Dw`, `Da`, `Tg` | IMU intrinsics, in the configured convention |
| `b_g`, `b_a` | Biases |
| `t_ga` | Gyro↔accel offset (the time offset between the gyroscope and accelerometer channels), when estimated |
| `gyro_only` | Per-IMU flag — the result self-documents which IMUs skipped the accel |
| source topic | Per sensor; this is what lets `apply-calib` derive the topic→sensor map without a hand-written file |

:::caution[Intrinsics are convention-dependent]
`Dw` / `Da` are only comparable between calibrations that used the same
`imu_intrinsics_model`. Read the convention before comparing numbers — see
[IMU model](/concepts/imu-model/).
:::

### Batch layout

With `input.bags`, each sequence gets its own discoverable result:

```
<output_dir>/
  bag00/cam_imu.json
  bag01/cam_imu.json
  bag02/cam_imu.json
```

The repeatability study reads this layout.

## HTML report

We write one self-contained file per run. It has no external assets, so it can be emailed.
It uses print-friendly CSS.

Contents:

- **Navigation:** navigable TOC (table of contents) and summary stat cards
- **Intrinsics and distortion:** tables
- **Extrinsics:** with an inline 3D plot
- **Temporal calibration:** time offset and readout together
- **Reprojection analysis:**
  - per-frame robust median and P95 (95th percentile)
  - per-tag
  - error-vector histograms
  - dual-panel scatter
  - corner heatmaps
- **Calibration-data quality:**
  - motion-excitation metrics with grades
  - rotation-axis spread
  - angular-velocity timeline
  - feature-coverage heatmap
- **Detection statistics**
- **Pipeline timing**
- **Appendices:** collapsible

To rebuild reports without recalibrating, run this. It uses the saved YAML plus the detection cache:

```bash
python -m mvis.analysis.regenerate_html
```

## Kalibr interop

`mvis.io.kalibr` is the one surface for Kalibr files:

| Function | Direction | Handles |
|---|---|---|
| `read_camchain` | in | Intrinsics + distortion across pinhole / ds / eucm / fov |
| `read_camchain_imucam` | in | Also each camera's `T_cam_imu` and stereo `T_cn_cnm1` |
| `write_camchain_imucam` | out | Exports a cam-IMU result as a round-trippable camchain-imucam |

With these, a Kalibr calibration becomes an MVIS starting point.
A MVIS result can also go back into a Kalibr-expecting pipeline.

## Ground-truth comparison

Per-dataset ground-truth YAMLs live under `examples/regression/gt/`.
Where one exists, the dashboard annotates each parameter with its deviation.
For example: `Δ +0.27% GT=190.97`, colour-coded by accuracy band.

## Corrected bags

[`mvis apply-calib`](/guides/roundtrip/#export-a-corrected-dataset) writes a corrected ROS1 bag.
It also writes a **provenance sidecar**: a file recording which calibration was applied and what it changed.
The bag is ordinary. Anything that read the original reads the corrected one.
