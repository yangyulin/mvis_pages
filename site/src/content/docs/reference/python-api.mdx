## Package layout

| Module | Contents |
|---|---|
| `mvis.core` | Types — `Observation`, `CameraParams`, `CalibrationResult` — plus config dataclasses |
| `mvis.camera` | One `CameraModel` per distortion model; projection, Jacobians, unprojection in one place |
| `mvis.board` | Detection — chessboard, AprilGrid, ArUco — and `corner_subsample` |
| `mvis.io` | `DataLoader`, streaming `DetectionPipeline`, data sources, detection cache, frame selector, output writers |
| `mvis.calibration` | Initialiser (OpenCV PnP), Optimizer (the unified factor), Pipeline, `outlier_rejection`, `camera_projection`, `custom_projections` |
| `mvis.analysis` | HTML report, plotting, Rerun 3D visualisation, motion analysis |
| `mvis.recalib` | `apply-calib` — corrected-dataset export |
| `mvis.cli` | Command-line interface |

Terms in the table:

- **Jacobians:** the derivatives of the projection.
- **Unprojection:** the reverse of projection, from a pixel back to a viewing ray.
- **OpenCV PnP:** OpenCV's pose-from-known-points solve, used for the first guess.

## Kalibr interop

Use `mvis.io.kalibr` for all Kalibr files. It is the one surface for them.

| Function | Does |
|---|---|
| `read_camchain` | Intrinsics + distortion across pinhole / ds / eucm / fov |
| `read_camchain_imucam` | Also recovers each camera's `T_cam_imu` and the stereo `T_cn_cnm1` |
| `write_camchain_imucam` | Exports a cam-IMU result as a round-trippable camchain-imucam |
| `apriltag_board.from_kalibr_yaml` | Loads an AprilGrid target definition |

A camchain is Kalibr's YAML file of camera parameters. `T_cam_imu` is the
IMU-to-camera transform. `T_cn_cnm1` is the transform from the previous camera
to this one.

This module is the practical path for comparing against Kalibr or migrating from it.

## Regenerating reports

This command rebuilds HTML reports without re-running the calibration:

```bash
python -m mvis.analysis.regenerate_html
```

- **Inputs:** saved YAML plus the detection cache
- **When to use it:** only the report template changed

## Why the models live in one place

A report cannot disagree with the fit it describes. Reported residuals are
computed by the same code the solver minimised.

This is a deliberate constraint:

- **`camera/CameraModel`** holds each model's projection, Jacobian, and unprojection together.
- **`calibration/camera_projection.py`** is shared by the optimiser *and* the HTML report.
