Results — repeatability across recordings

Batch 2026-11-08a · results commit e893730 · records in calibench-vi/results · the Space shows the same parameter tables.

Overall VI-Rig 3 camsVI-Rig 4 camsTUM-VILooper Insight-9Monado MGC

This page shows repeatability, not accuracy. Repeatability is how much each tool’s estimates scatter when the same rig is calibrated from different recordings. These datasets have no ground truth, so no tool is the reference, and a tool can repeat well and still be biased. Tools are compared only on recordings that every compared tool ran. Reprojection error measures how well a model fits its own data; it is not used here. The MVIS authors run this board and made every run, including the Kalibr and Basalt runs.

Run dates and data settings

Kalibr camera + IMU on T6 and T11 was re-run on 2026-11-07 from its own camera calibration. On 2026-11-08 MVIS and Kalibr on T6 and T11, and Basalt on T11, were re-run with IMU noise measured at rest (white-noise density × 2.5, the same values for every tool; bias walks at the defaults). MVIS on T2 and T12 was re-run on 2026-11-08 with the current MVIS code. On T3 every tool ran on the same view-filtered bags (≤ 85°) on 2026-11-07, and the T6c MVIS values come from camera-only runs. Kalibr on T7 was re-run on 2026-11-02, and the Kalibr runs for T1 bag 09 on 2026-11-04. Other Kalibr and Basalt runs are from 2026-10-22 or earlier. Data settings still differ from MVIS on T6, T7 and T8.

About these results

Section titled “About these results”
How the verdicts are made

For each family and group of parameters we take only the recordings every compared tool ran. For each tool we measure the scatter (standard deviation) of each parameter across those recordings, and compare two tools by the median ratio of their scatters. A tool is marked more repeatable only if its scatter is at least 20 % smaller and a gap that large would rarely appear (under 5 %, Holm-adjusted within the cell) if we swapped the two tools’ results recording by recording. Otherwise it is a tie: either the gap is within chance, or it is under 20 %. With fewer than 6 shared recordings no gap can pass this test (the smallest possible p is 2/2ⁿ), so those cells say “too few recordings”. Values a tool received as input, and rows where the tools’ models differ, are not compared. Distortion coefficients trade off against each other, so their scatter can overstate differences in the lens mapping. Each cell is a separate 5 % test; across the 27 tested cells on this page, of which 14 name a tool, one or two calls may be chance. The intervals are not adjusted for multiple tests.

Agreement between tools

The parameter tables also show the differences between the tools’ medians. Where two tools’ medians differ by more than either tool’s scatter, they disagree. ◆ marks disagreement, not an error in either tool. No tool is the reference. ‡ on a time offset: MVIS splits the gyro (td) and accel (td + t_ga) timelines, so Basalt − Kalibr is the like-for-like check there.

How to read the parameter tables
How to read this
  • Spread shows repeatability across recordings, not accuracy. A tool can repeat well and still be biased.
  • 448.50 ± 0.48 (10): median ± sd across the 10 recordings that tool solved. With 3 or 4 recordings the sd itself is rough.
  • (3/15): this tool has 3 of the family's 15 recordings.
  • fixed: Kalibr doesn't estimate this value. Its camera + IMU runs take intrinsics and baselines as input, from an MVIS export or, on T6 and T11, from its own camera-only calibration; T7 ELP-L readout is held at 0. The spread here isn't repeatability.
  • shown: the tool uses a different model here, so the value has no difference next to it.
  • other model: Kalibr's coefficients here belong to a different lens model.
  • not in model, not reported, no run, no data, no RS model, not in one run: the tool has no value for this row, and the words say why. no run means the tool never ran with this sensor; not in one run means it ran with each sensor, but no single run holds both ends of the baseline. not run, in the recordings line: the tool has no run for the family.
  • Differences: the column header gives the subtraction, using stored medians. No tool is the reference.
  • ◆: the difference is larger than the larger of the two sds. It marks disagreement, not an error in either tool.
  • ≠n: the two medians come from different numbers of recordings.
  • ≠ model: the tools' models differ, so no difference is shown. fit: reprojection error measures fit and isn't comparable across models.
  • ‡ td: MVIS splits the IMU into gyro (td) and accel (td + t_ga); Kalibr and Basalt have one timeline. Basalt − Kalibr is the like-for-like check.
  • Each family folds; the first is open. Click a family's title to open or close it.
