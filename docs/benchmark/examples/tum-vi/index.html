Demo and values

Section titled “Demo and values”

One MVIS camera + IMU run on dataset-calib-imu1, and how close it lands to TUM's published Kalibr calibration.

Reprojection median0.10 px
cam0–cam1 baseline101.1 mm

Reprojection is how far, in pixels, the detected corners lie from where the solve puts them. td is the camera–IMU time offset, and the lever arm is the camera–IMU position offset.

Check against a reference

Section titled “Check against a reference”

Reference: TUM's published camera + IMU calibration for the 1024 × 1024 data, Kalibr pinhole-equidistant (the kb4 model), from the TUM VI dataset page.

td ms+0.159not in TUM's calibration file

Δp is the distance between the two lever arms. Δθ = ‖log(RaT Rb)‖, the angle between the two rotations. A reference, not ground truth: it was solved by another tool on the same kind of data.

The rotation differs by about 9.4 mrad on both cameras. That offset is systematic: MVIS gives the same rotation on all four TUM calibration recordings. It is not explained yet. One possible cause, not verified: this run uses the raw IMU, while TUM's Kalibr run used an IMU model it had already calibrated, so the two IMU frames may differ by a small rotation.

Lens model note: on these lenses the kb4 polynomial folds back inside the image, past about 114° (682 px from the centre) on cam0 and 119° (705 px) on cam1. The model gives no ray beyond that radius.

Config and run

Section titled “Config and run”

The marked lines are the choices that matter for this rig:

  • input.window_mode: MVIS picks the 80 s window with the most motion.
  • camera_input.path: Seed intrinsics: kb4 values from MVIS camera-only solves of TUM's eight camera recordings.
  • camera_input.cameras: cam1 is added to the graph at 8 Hz, which keeps the solve small.
  • solve.estimate_t_ga: Estimates t_ga, the time offset between the gyroscope and the accelerometer.
  • estimate.camera.intrinsics: Camera intrinsics stay free in the camera + IMU solve.
  • estimate.imu: The gyro and accelerometer scale and misalignment (dw_da) are estimated too. IMU noise is left at the MVIS defaults.

This is the config of the run on this page, with every path cut to its file name. Point the paths at your copy.

The solve took about 4 min on one desktop. It writes cam_imu.json, a calibration YAML and a report beside the config.

Dataset

Section titled “Dataset”
  • Recording dataset-calib-imu1, the first of TUM's four camera + IMU calibration recordings, at 1024 × 1024.
  • Cameras: two global-shutter fisheye cameras at 20 Hz, fitted with the kb4 (Kannala-Brandt) lens model. IMU: Bosch BMI160 at 200 Hz.
  • Board: AprilGrid 6×6, tag 88 mm, spacing 0.3, t36h11.
  • Solve window: 48.9 s.

Download: TUM VI dataset page → The recordings are listed there, not copied here.
