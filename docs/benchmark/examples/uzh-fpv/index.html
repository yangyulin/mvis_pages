UZH-FPV

The UZH-FPV Drone Racing dataset ships camera-IMU calibration bags for two devices, recorded indoors and outdoors with the camera at 45° and facing forward. We ran MVIS, Kalibr and Basalt on all 8 bags and show them in the same table as the leaderboard. This is a one-off study, not part of the leaderboard or the regression suite.

There is no ground truth. Differences show where tools disagree, not who is right. The MVIS authors made every run, including Kalibr and Basalt.

IMU weights

Section titled “IMU weights”

All three tools use IMU sigmas taken from the residuals in UZH’s own Kalibr results, not the MVIS defaults. UZH publishes no measured IMU noise, and the sigmas in its imu.yaml are the same on all 8 bags (gyro 0.05, accel 0.1). For each bag we take the RMS of Kalibr’s 3-axis residual norm and divide by √(3 × IMU rate). That gives gyro 3.0–8.5e-4 rad/s/√Hz and accel 1.1–5.2e-3 m/s²/√Hz, against the MVIS defaults of 1e-2 and 2e-2. Bias sigmas keep the MVIS default ratio of 0.1. These are estimates, not measured noise.

The choice matters most on the Davis. On its forward bags, the difference between the indoor and outdoor MVIS rotation is 4.1 mrad with these weights and 38.9 mrad with the defaults. Snapdragon moves less, and its forward bags get slightly worse, from 2.2 to 4.2 mrad.

Results

Section titled “Results”
How to read this
  • Spread shows repeatability across recordings, not accuracy. A tool can repeat well and still be biased.
  • 448.50 ± 0.48 (10): median ± sd across the 10 recordings that tool solved. With 3 or 4 recordings the sd itself is rough.
  • (3/15): this tool has 3 of the family's 15 recordings.
  • fixed: Kalibr doesn't estimate this value. Its camera + IMU runs take intrinsics and baselines as input, here from the calibration UZH ships. The spread here isn't repeatability.
  • shown: the tool uses a different model here, so the value has no difference next to it.
  • other model: Kalibr's coefficients here belong to a different lens model.
  • not in model, not reported, no run, no data, no RS model, not in one run: the tool has no value for this row, and the words say why. no run means the tool never ran with this sensor; not in one run means it ran with each sensor, but no single run holds both ends of the baseline. not run, in the recordings line: the tool has no run for the family.
  • Differences: the column header gives the subtraction, using stored medians. No tool is the reference.
  • ◆: the difference is larger than the larger of the two sds. It marks disagreement, not an error in either tool.
  • ≠n: the two medians come from different numbers of recordings.
  • ≠ model: the tools' models differ, so no difference is shown. fit: reprojection error measures fit and isn't comparable across models.
  • ‡ td: MVIS splits the IMU into gyro (td) and accel (td + t_ga); Kalibr and Basalt have one timeline. Basalt − Kalibr is the like-for-like check.
  • Each family folds; the first is open. Click a family's title to open or close it.

No ground truth: ◆ marks disagreement, not who is right.

Read first: All three tools use each bag's IMU weights from the residuals in UZH's own Kalibr results. Kalibr's intrinsics and baseline are inputs from the calibration UZH ships.

Notes

Like for like: Every tool starts from the camera chain UZH ships and uses the same IMU sigmas on the same bags. Kalibr keeps the camera values fixed; MVIS and Basalt refine them.

Reading these results

Section titled “Reading these results”
  • One Basalt solve is left out. On davis_indoor_forward with these weights, Basalt gives a 120 mm lever and an accel scale of 0.84, so its Davis column has 3 of 4 bags. At Basalt’s default noise that bag is plausible, but snapdragon_indoor_45 then fails with a broken spline.
  • Basalt’s Davis distance stands out. Its camera-to-IMU distance is 33.6 mm, against 23.2 mm from Kalibr and 22.8 mm from MVIS on the same 3 bags. We haven’t established why. At default noise Basalt’s lever z is 14–25 mm.
  • Each device’s 4 bags form one family, because the camera and IMU are on the same device. That assumes the camera-IMU geometry stayed the same across recordings, which we can’t confirm.
  • Snapdragon’s time offset really does differ between bags, with an sd near 4.7 ms in every tool, so a small difference between tools on that row says little about each bag.
  • Rotations aren’t in this table, the same as on the leaderboard, because the IMU models define the IMU frame differently.
