Demo and values

Section titled “Demo and values”

One MVIS camera + IMU run on recording 4imus_4cams_01: all four cameras and all four IMUs solved together.

Reprojection median0.25 px
cam0–cam1 baseline63.7 mm
cam0 td−5.41 ms

Reprojection is how far, in pixels, the detected corners lie from where the solve puts them. td is the camera–IMU time offset, and the lever arm is the camera–IMU position offset.

Config and run

Section titled “Config and run”

The marked lines are the choices that matter for this rig:

  • input.imu_topics: Four IMU topics. The first is the base IMU; the other three are solved against it.
  • input.window_mode: MVIS picks the 80 s window with the most motion.
  • camera_input.cameras: The ELP cameras are rolling shutter, so their readout time is estimated. The three cameras after the first are added to the graph at 4 Hz, which keeps the solve small.
  • solve.sigma_g: The same IMU noise values as the 3-camera example, which has the same Xsens base IMU.
  • estimate.board_points: The printed board is not quite flat, so its shape is estimated too.
  • estimate.camera.intrinsics: Camera intrinsics stay free in the camera + IMU solve.

This is the config of the run on this page, with every path cut to its file name. Point the paths at your copy.

The solve took about 12 min on one desktop. It writes cam_imu.json, a calibration YAML and a report beside the config.

Dataset

Section titled “Dataset”
  • Recording 4imus_4cams_01, one of the 15 recordings of this rig. MVIS picks the 80 s window with the most motion.
  • Cameras: the two T265 fisheye cameras (global shutter) and the ELP stereo pair (rolling shutter), all with the equidistant lens model.
  • IMUs: the Xsens MTi is the base IMU; the two MicroStrain units and the T265's own IMU are solved against it.
  • Board: AprilGrid 6×6, tag 88 mm, spacing 0.3, t36h11.
  • Solve window: 80.0 s.
