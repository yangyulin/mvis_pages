Why calibrate t_ga

Use this page to decide whether to calibrate t_ga (the time offset between the gyroscope and the accelerometer inside one IMU), and to see what happens to td (the camera–IMU time offset) when a tool cannot model it.

MVIS fits t_ga. Kalibr (one time shift per camera) and Basalt (one camera time offset for the whole rig) treat the IMU as one clock. If the accelerometer is off that clock, the offset has to go somewhere else.

On two real IMUs, MVIS measures t_ga of about −5 to −6 ms. On the same bags, Kalibr’s and Basalt’s td differ from MVIS by about 3 ms (Looper Insight 9) and about 2 ms (Intel T265). The sweep below predicts 3.0–3.2 ms and 1.6–1.7 ms of that from the offset alone.

This page shows where an offset goes, not which tool is right.

  • Shown: a real gyro–accel offset of −5 to −6 ms on two IMUs. Tools with one IMU clock move td by a steady share of an injected offset, and that share explains most of the td gap on the raw bags.
  • Not shown: whose td is closer to the truth on raw data. That test is still open.
  • Built in our favour: the sweep injects exactly the model MVIS fits (a pure accel shift, linear interpolation). MVIS recovering it is a consistency check, not proof of accuracy.
  • Round trips cannot order tools: every tool returns to about zero on a bag it corrected itself.
  • Small sample, our runs: one recording per device. The MVIS authors ran all three tools.

All limits: Limits.

Short answer

Section titled “Short answer”

  • Turn it on: the default is off.

    See Configuration and Estimate t_ga.

  • Sign: the accel stored at stamp t is taken as sampled at t − t_ga. A negative t_ga means the accel is stamped early: it leads the gyro on the stamp timeline. Both devices here read negative.

  • If t_ga is near zero (well under 1 ms, within 2σ): MVIS sees no offset under its pure-shift model. That does not rule out a frequency-dependent response like the T265’s. A real-data control on such an IMU has not been run yet.

  • If t_ga is 1 ms or more in size: for an offset that is a pure shift, as injected here, a one-clock tool moves td by 0.28–0.64 × t_ga. Whether that is its error on raw data is not tested.

    The share depends on the IMU and the motion. It is not a constant of the tool.

  • IMU scale moves very little: under 0.06 % between τ = 0 and −5 ms. In this test the offset shows up in td, not in scale.

  • If you must use a one-clock tool: expect td to carry part of the offset, or remove it first with corrected-dataset export. On the MVIS-corrected bags, Kalibr and Basalt read td within 0.3 ms of zero (T265 −0.16 / −0.20 and −0.28; Looper −0.03 / −0.04 and −0.01). That is a self-consistency read. Whether a pre-shift gives Kalibr or Basalt the true td is not tested.

Older run, t_ga off

On older MVIS code, april_01 with t_ga off gave td −9.60 / −12.28 ms, against −7.60 / −10.29 ms with it on. That is close to Kalibr’s −9.85 / −12.61 ms. It is the only run where MVIS itself turned t_ga off, and it has not been re-run on current code.

The offset is real

Section titled “The offset is real”
  • What t_ga is: see IMU model. A common cause is a driver that resamples or filters the accel. The T265 driver places a 62.5 Hz accel onto 200 Hz gyro stamps.
  • Looper Insight 9: t_ga −5.03 ± 0.02 ms on looper_1.
  • Intel T265: −5.69 ± 0.43 ms on VI-Rig april_01. Older runs on other april recordings read −5.88 to −8.07 ms. The T265 sensor page reads −6.59 ± 0.43 ms from one recording, in a different run set.
  • Without the solver: an estimator-free correlation check on twelve older Looper recordings (10 hand-held, 2 arm) read −5.8 to −7.1 ms, against −5.0 to −5.5 ms from an older solver run; the check reads about 1.2 ms more negative than the solver (bias −1.24 ± 0.42 ms). On ten T265 recordings it read −6.05 ± 0.14 ms at 2–25 Hz.
  • On the T265 the offset shrinks with frequency (Figure 2). One t_ga is a compromise for the motion.

The sweep: delay the accelerometer, watch td

Section titled “The sweep: delay the accelerometer, watch td”
  • Start from a fair zero: the MVIS-corrected bag, with a common crop. On it all three tools read td near zero.
  • Delay only the accel by τ = −50, −20, −10, −5, −2, 0, 2, 5, 10, 20 and 50 ms: a′(t) = a(t − τ). That is 11 bags per device. The 0 ms bag is the corrected bag with the same crop. In MVIS’s sign, the true t_ga is τ.
  • Run all three tools on every bag with their usual settings.
  • Read td and t_ga.

Would you notice it?

Section titled “Would you notice it?”
  • No warning: Kalibr and Basalt converge at every τ.
  • Reprojection barely moves: near the real offset (τ 0 to −5 ms) it does not change. Even at ±50 ms it rises only 10–16 %, which is easy to miss.
  • Kalibr gyro error grows, but slowly: at τ = −5 ms it is × 2.4 on Looper and × 1.2 on the T265, against τ = 0. At −50 ms it is × 21 and × 5.3.
  • A self round trip will not catch it: Kalibr’s own round trip on Looper returns +0.0006 ms.
  • What does catch it: a run with t_ga on, or an estimator-free correlation check.
IMU scale under the sweep
  • At real offsets (τ 0 → −5 ms): Kalibr moves at most 0.03 % (Looper) and 0.062 % (T265); Basalt at most 0.032 % and 0.055 %. MVIS spans at most 0.002 % and 0.005 % over the whole sweep.
  • Looper shape: gyro y follows the size of τ, not its sign. Kalibr +0.96 / +1.51 % and Basalt −1.65 / −1.84 % at −50 / +50 ms.
  • T265 shape: Kalibr’s accel scale follows the sign of τ: −0.09 / −0.12 / +0.09 % per 10 ms on x / y / z.
  • Basalt’s T265 offset: gyro x +1.22 % and accel z +1.50 % are already there at τ = 0. From −10 to +10 ms gyro x stays within 0.1 % of that and accel z within 0.13 %. The offset does not cause them.

Limits

Section titled “Limits”
  • Which td is true is not tested: the page explains the gap, not which value is right. A clock check through a third IMU, camera-td injection and a control on an IMU with t_ga near 0 are still open.
  • The sweep uses our model: a pure accel shift with linear interpolation, which is exactly what MVIS fits. A slope of 1.000 / 0.998 is consistency, not accuracy. A real offset that is not a pure shift fits less well.
  • Round trips cannot order tools: self residuals on the T265 are MVIS +0.19 / −0.06, Kalibr −0.019 / −0.019 and Basalt −0.00002 ms.
  • The T265 offset depends on frequency: −6.76 ms at 2–4 Hz to −1.17 ms at 30–40 Hz. Coherence falls above about 22 Hz, so the top two bands are less certain. So −5.69 ms is a compromise for this motion; other recordings read −5.88 to −8.07 ms.
  • First-order model: MVIS corrects t_ga to first order; the ½·t_ga²·ä term is ignored, which matters at large offsets. A re-linearised version is being tested and is not in MVIS yet.
  • Open questions:
    • Why the T265 share (0.30) is about half Looper’s (0.64). Unchecked candidates: the 62.5 Hz accel interpolated onto the gyro stamps, different motion, part of the offset going into scale.
    • MVIS on the Kalibr-corrected Looper bag reads t_ga −2.65 ms (expected −5.03), RMS 0.47 px and gyro x scale 1.0069. It is unexplained, and it does not repeat on the T265 (−5.44 ms).
    • On the T265 the sweep predicts the raw Kalibr gap 0.2–0.25 ms short.
  • One recording per device: april_01 and looper_1. The other recordings have not been run.
  • Basalt has one offset for the rig: on the T265 its gap is −2.02 ms against cam0 and +0.68 ms against cam1.
  • Settings differ: Kalibr uses 10 Hz frames, Basalt every second frame with its own camera calibration, MVIS 30 Hz. Intrinsics are pinned on the T265 and free on Looper.
  • The t_ga-off row is from older code and has not been re-run.
  • The MVIS authors ran every tool.

Replay it yourself
  1. Download one sweep folder from the Hub (you need to accept the gate first).
  2. Run each tool on each bag with your usual settings: mvis cam-imu -c cam_imu.yaml with estimate_t_ga: true, Kalibr’s kalibr_calibrate_imu_camera, and basalt_calibrate_imu.
  3. Read td (and t_ga for MVIS) and fit each tool’s td against τ. The true values in every bag are t_ga = τ, td = 0, identity IMU scale and zero bias.

To build a sweep from your own recording: correct it with mvis apply-calib, crop it, then delay only the accel channel by τ with linear interpolation, as each folder’s README describes.

This page uses april_01 only. The T265 sensor page’s −6.59 ± 0.43 ms is from another run set.
