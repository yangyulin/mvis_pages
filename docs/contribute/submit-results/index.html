Submit results

Submissions are paused

Submissions are not being accepted while this process is replaced by a new kit. The format below is the old one. Entries in it will not appear on the leaderboard. The leaderboard is built from the maintainers’ runs of MVIS, Kalibr and Basalt.

Use this page to submit your calibration method to the Open MVIS leaderboard. In short:

  • How: open a pull request (PR, a request to merge your change) against the Open MVIS site repo.
  • What: add a single YAML file that follows the schema below (the fixed set of fields a submission has).
  • Checks: the CI on the PR (the checks that run automatically) validates the schema. It then rebuilds the site with your entry included.

Submission schema

Section titled “Submission schema”

Category values

Section titled “Category values”

Use one of these sensor_config.category values:

  • cam_only_mono
  • cam_only_stereo
  • cam_only_multi
  • single_imu_single_cam
  • single_imu_multi_cam
  • multi_imu_single_cam
  • multi_imu_multi_cam

Family values

Section titled “Family values”

Use one of these method.family values:

ValueMeaning
discrete_factor_graphGTSAM / Ceres batch MAP (all data solved at once for the most likely values)
continuous_time_bsplineSE(3) B-splines (smooth curves of the pose over time; Kalibr, Basalt)
filter_ekfonline EKF (an extended Kalman filter that updates as data arrives; OpenVINS-style)
learning_baseddeep-network regression
otherhybrid or none of the above

Filing the PR

Section titled “Filing the PR”
  1. Fork yangyulin/mvis_pages on GitHub.
  2. Drop your YAML at site/src/content/leaderboard/<method>__<config>.yaml.
  3. (Optional) Add a full HTML report and raw YAML at site/public/reports/. Reference them in the artifacts block.
  4. Open a PR. The schema is validated on build, and the CI preview will show the new row immediately.
  5. A maintainer will merge once the schema passes and the numbers look reasonable.

Reproducibility expectation

Section titled “Reproducibility expectation”

For external submissions we expect one of these:

  • A public repo where anyone can reproduce your numbers, or
  • A paper citation whose experimental protocol matches the submission, or
  • Both.

Verification

Section titled “Verification”

For now, submissions are self-reported. The submitted.by and submitted.hardware fields carry the accountability trail: who submitted and on what hardware.

A future version of the leaderboard will offer server-side evaluation (results computed on the server, not reported by you). It will run on hidden ground-truth sequences (recordings whose true values are not published). This is the model used by the Hilti SLAM Challenge.
