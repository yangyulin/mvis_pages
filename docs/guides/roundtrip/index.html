Round-trip validation

Step 8 of the walkthrough. Here you check the calibration on real data, where there is no ground truth.

  • You need: the camera–IMU config from step 4. It must read a ROS1 bag.
  • You get: PASS or FAIL, with a check list.
  • Check: read the check list (section 2). A FAIL is a finding, not a flaky test.

Why a round trip:

  • Reprojection error (how far the detected corners land from where the calibration predicts them) tells you a calibration fits its own data. It does not tell you the calibration is right.
  • A round trip does. We apply the calibration to the data it came from, then calibrate again. If the first answer was right, there is nothing left to find.

1. Run it

Section titled “1. Run it”

One command runs four steps:

  1. Calibrate (calibration A).
  2. Correct the bag with mvis apply-calib.
  3. Calibrate the corrected bag (calibration B).
  4. Compare A and B and report PASS or FAIL.

It exits non-zero on FAIL, so it can run in CI.

FlagEffect
-c, --configThe camera–IMU config to check (ROS1 bag)
--outOutput folder (default results/roundtrip/<config name>)
--bagUse this ROS1 bag instead of the config’s source
--keep-correctedKeep the corrected bag (deleted by default)
--keep-biasDo not remove the IMU biases in step 2
  • Disk space: the corrected bag is written next to the raw bag and is about as large. After calibration A, MVIS checks the disk has room for it and stops if not.
  • Detection cache: the corrected bag gets its own name, so its corners are detected afresh.
  • Output: report.txt and report.json in the output folder, with the results of both calibrations in forward/ and recal/.
  • EuRoC input: convert the folder to a ROS1 bag first, then pass it with --bag. For a catalog dataset use mvis datasets convert --dataset <key>; for any mav0 folder call mvis.datasets.converters.euroc_folder_to_rosbag.convert_euroc_folder_to_rosbag(src, "out.bag").

2. What PASS means

Section titled “2. What PASS means”

PASS needs two things. They pull in opposite directions, which is what makes the test useful.

  • Collapse. On the corrected bag, every IMU’s Dw and Da (the gyroscope and accelerometer scale and misalignment matrices) must go to identity, and the biases b_g and b_a to zero. Calibration A claimed to measure them; if it was right, the correction used them up.
  • Preserve. Each camera’s lever arm (its position in the base IMU frame) must not move, nor must the stereo baseline between the first two cameras. The correction changes timing and IMU scaling, not geometry. A lever that moves means calibration A traded geometry against something else.

The limits:

  • Dw and Da: every diagonal entry within 1 % of 1.
  • Biases: below 0.02 (rad/s for the gyroscope, m/s² for the accelerometer).
  • Lever arms and the stereo baseline: at most 2 mm of drift.

The timing terms are warnings, not failures: each camera’s td (time offset to the base IMU) and each IMU’s t_ga (gyroscope-to-accelerometer offset). How much of them survives depends on how well the data observes them. The aux IMUs’ td is not checked.

  • In report.txt: every timing row is marked warn, whatever its value. It only means the row is a warning-only check. The value should be near 0; above 2 ms it is worth a look.

3. Limits on this rig

Section titled “3. Limits on this rig”
  • Rolling shutter is not tested. apply-calib re-stamps each frame but does not unwarp its rows. So a round trip on the ELP pair does not check its readout.
  • Use other checks for the readout: Rolling-shutter calibration and the digital-twin check.

Export a corrected dataset

Section titled “Export a corrected dataset”

mvis apply-calib is the correction step inside the round trip. You can also run it on its own. It takes a camera–IMU calibration and a raw ROS1 bag, and writes a new bag with the calibration applied:

  • IMU intrinsics removed: scale, misalignment and g-sensitivity.
  • Biases removed.
  • One timeline for every stream.

Downstream tools then get corrected data and need to know nothing about the calibration.

Run apply-calib

Section titled “Run apply-calib”

With flags:

Or from a config file:

  • Calibration: mvis cam-imu writes cam_imu_calib.yaml next to cam_imu.json. Pass that YAML to --calib.
  • Output: defaults to <input>.corrected.bag. An existing bag is not overwritten.
  • Topics: the calibration records each sensor’s source topic, so MVIS finds which topic belongs to which sensor. Use --map only to override that.
  • Example config: examples/configs/recalib_example.yaml in the MVIS repo. It lists every config key.

What gets corrected

Section titled “What gets corrected”
CorrectionDetailTurn off with
IMU intrinsicsDw, Da and Tg removed through the inverse IMU model--no-imu-intrinsics
Static biasThe calibrated biases subtracted--keep-bias
Time alignmentEvery camera and aux IMU re-stamped onto the base IMU clock by its td--no-td
Gyroscope-to-accelerometer offsetThe accelerometer re-sampled at t + t_ga, when t_ga was calibrated--no-t-ga
UndistortionImages undistorted (mono8 images only)on only with --undistort

The terms:

  • Dw / Da: the scale and misalignment of the gyroscope and the accelerometer.
  • Tg: the g-sensitivity, how linear acceleration leaks into the gyroscope.
  • td: the time offset of a sensor to the base IMU.
  • t_ga: the time offset between the gyroscope and the accelerometer.

More flags:

  • --strict: stop on missing or empty topics, wrong message types, duplicate IMU stamps and non-finite values, instead of passing them through.

Re-stamping uses the header clock

The correction works on each message’s header stamp, the time the sensor reported. Working on the bag’s record time instead would bake each topic’s receive latency into the corrected bag, and turn a driver artefact into permanent data.

Many recordings

Section titled “Many recordings”

One calibration usually serves many recordings of a rig. To correct a whole folder of bags, run scripts/recalib_batch.py --calib cam_imu_calib.yaml --in-dir raw/ --out-dir corrected/ from the MVIS repo. It runs the same correction as apply-calib on every *.bag in the folder.

The t_ga study starts from such a corrected bag: Why calibrate t_ga.

When it fails

Section titled “When it fails”

A FAIL is a real finding. The usual causes:

  • Wrong camera model. The intrinsics absorbed an error that comes back once the timing is corrected. Try another camera model.
  • Wrong IMU convention. See IMU model.
  • An interpolated accelerometer that corrupts td, as on the T265. The fix is gyro_only on that IMU, or estimating t_ga. A round trip alone does not catch this case: a tool with no t_ga also returns to about zero on its own corrected bag. Turn t_ga on and read it. See Why calibrate t_ga.
  • Not enough motion. The parameter was never observed, so correcting by it does nothing consistent.
